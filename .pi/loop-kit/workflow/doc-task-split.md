本文件描述「doc-to-tasks 拆分」的标准：读父条目的输出文档，把它拆成可并行执行的 `quick` 子条目。

# 输入

- 父条目 id 与输出文档路径（绝对路径 + 仓库根相对路径）。
- 可选的父级参考文档（`docParent`），只读，用来保持术语与边界一致。
- 可选的上一次否决理由：只有确实需要调整拆分时才改。

# 流程

- 只读输出文档与代码现状，不实现、不改文档、不创建条目。
- 输出 2–12 个子条目；每个子条目应当一次提交可完成，写集必须与兄弟子项不相交。
- 每个子条目必须声明非空 `touch`（仓库根相对 glob 数组，格式同实现文档的
  `## 改动范围`）；缺失、空数组、绝对路径、`..` 或换行都会判定拆分失败。
- 文档只作人类视图，任务 `touch` 才是执行数据源：共享同一父文档不会让兄弟子项串行；
  确实需要共同修改同一文件的工作应合并为一个子项。
- `key` 用 kebab-case 且唯一；`title` 是中文短语；`tag` 从 `feat` / `fix` /
  `refactor` / `docs` / `test` / `chore` 中选；`desc` 写清交付物与验收要点。
- 用 `deps` 表达先后序（引用其它子条目的 `key`）；没有依赖的子条目会并发执行。
- 拆分粒度以「能独立验收」为准：不要把同一文件的无关改动硬拆成多个子条目。
- 父条目已经预设 `doc` 输出文档时，子条目会继承该文档作为 `doc`；不要另建文档路径。

# 输出

回复末尾输出唯一一个 ```json 围栏块：

```json
{
  "version": 1,
  "parent": "#123",
  "children": [
    { "key": "api", "title": "补齐 API", "tag": "feat", "desc": "…", "touch": ["pi/src/api/**"], "deps": [] },
    { "key": "ui", "title": "接入 UI", "tag": "feat", "desc": "…", "touch": ["pi/src/ui/**"], "deps": ["api"] }
  ]
}
```

- `version` 固定为 `1`；`parent` 是父条目 id（带 `#`）。
- `children` 至少 2 个、至多 12 个；`deps` 可以省略（等价于空数组）。
- `touch` 必填且非空；兄弟子项的写集不得相交。
- 围栏块之外可以写简短说明，但不要再输出第二个 JSON 代码块。

# 验证

- 编排器会校验：子条目数量、`key` 格式与唯一性、依赖存在且无环、
  `parent` 与当前条目一致；每个子项 `touch` 非空且路径合法，兄弟写集经调度器同一套
  glob 语义判定为不相交。
- 拆分执行后每个子条目被设为 `quick`，`doc` 指向父输出文档，`touch` 写入任务级写集
  （新建时写入；复用已有子项时只补缺，不覆盖已有值）。

# 提交与边界

- **不提交**、不实现、不修改条目；拆分事务由编排器执行。

# 返回摘要

- 一句话说明拆分思路与子条目数量；JSON 围栏块必须完整。
