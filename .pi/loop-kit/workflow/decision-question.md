本文件描述「决策确认」阶段的标准（默认标准；项目可在 `loop/workflow/decision-question.md` 覆盖）。

本阶段只做一件事：读实现文档，把 `## 待确认决策` 段里需要用户拍板的条目用
`ask_user_question` 问清楚，并把答复写回文档。不写代码、不改条目 `status`、不提交。

# 输入

- 编排器给出实现文档路径（`doc` 字段，通常是 `loop/docs/<模块>/<时间戳>-<slug>.md`）。
- 只处理 `## 待确认决策` 段内的列表项，形如：

  ```markdown
  ## 待确认决策

  - [D1] 刷新按钮放在工具栏还是卡片内？ [待确认]
  - [D2] 失败时是否保留旧数据？ [待确认]
  ```

- `## 风险与未决`、`## 方案` 等其它段落**不算**待确认项；不要顺手提问或改写。
- 段不存在、段内为空、或只有「无」之类说明 → 直接说明「文档已完善、没有需要确认的条目」，
  结束本阶段（不派发、不创建任何文件）。

# 提问

- 用 `ask_user_question` 分批提问：每批 **≤4 题**，每题 **2–4 个具体选项**，并始终保留
  「其他（补充说明）」类选项（避开宿主保留词）；逐条对应一个决策项。
- 选项要具体、可执行（写明方案差异与代价），不要用「是 / 否」糊弄。
- 问题编号沿用文档里的 `[D1]`，方便用户与文档对照。

# 写回

- 答复写入文档的 `## 已确认决策` 段：保留原问题、原选项与所选结论（含「其他」的自由文本）。
- 同时把对应条目移出 `## 待确认决策`，保证中断重跑幂等：**已答过的不要再问**。
- 文档 header 的 `status` / `task_id` / `module` 等字段不动；只改正文上述两段。

# 异常

- 用户 dismiss、问卷超时、或工具报非交互（`--print` / 无 TUI）：把本轮采用的假设写进
  `## 已确认决策`（标注「假设」）并从待确认段移出，然后继续；**不重复追问**。
- 同一决策若用户明确「稍后再定」：保留在待确认段并原样记录，不要替他做决定。

# 边界

- 只改编排器指定的那一篇文档；不写代码、不改其它文档、不改条目 `status`、不提交。
- 不执行 `git push` 或任何远程写操作。

# 输出契约

最终回复给出简短摘要：确认了哪些决策（或为何无需确认）、仍待确认的条目；本阶段没有提交。
