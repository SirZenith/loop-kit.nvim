# 详情窗键值对卡片化

## 目标

把详情窗顶部的键值对区域从「`---` 分隔的 Markdown 列表」改成「分组卡片」：

- 状态信息、依赖与文档、提示词、执行信息各一张卡片；`decide` / `analysis` 也作为独立卡片，
  不再用 `---` 分隔。
- 卡片有最大宽度：窗口更宽时不超过上限，窗口变窄时随窗口收窄。
- 卡片内部键左对齐、值右对齐；一行放不下的值按聊天气泡方式折行，续行对齐到值列。
- 卡片边框使用注释色（`LoopKitMuted`），不引入新的高亮组。

详情窗其余部分（`# 任务描述`、`# 用户提示词`、`# 各阶段提示词` 及 Markdown 正文）保持
现状；编辑锚点、`decide` 数据与详情窗只读语义不变。

## 现状

`lua/loop-kit/render.lua` 的 `M.detail(task, opts)`（`:481`）把键值对写成 Markdown 列表：

- `field(key, value, value_hl)`（`:530-541`）输出 `- <key>: <value>`，并把
  `0..2` 与键名区间标成 `LoopKitDetailKey`，值区间标成调用方给的高亮组。
- `subfield`（`:542-555`）输出 `  - <key>: <value>`，用于 `analysis` 子项。
- `path_field`（`:557-561`）未设置时输出 `(未设置)` + `LoopKitDetailMuted`。
- `group_rule()`（`:585-590`）在组间插入 `空行 + --- + 空行`。
- `touch`（`:628-647`）单独输出 `- touch:` 与若干 `  - <path>` 行。
- `deps` 由 `deps_text`（助手定义于 `render.lua:409`，`:607-616` 调用）生成
  `#1, #2` 形式的字符串并携带 id 高亮区间。
- `analysis` 块（`:661-671`）先用 `---` 分隔，再写 `decide`、`analysis` 与四个子项。

调用方 `lua/loop-kit/ui/detail.lua:86-107` 的 `Detail:render` 只传 `tasks_by_id` 与
`analysis`，不知道详情窗宽度；详情窗尺寸变化时不会重排。

消费方：

| 位置 | 依赖 |
| --- | --- |
| `lua/loop-kit/edit.lua:224-290` | `M.target_at` 只用 `rendered.fields[key]` 的行号做最近锚点，不解析行文本 |
| `lua/loop-kit/ui/board.lua:806-808` | 按 `rendered.fields[...]` 跳转光标 |
| `tests/fake-dom/{kv,edit,board}_spec.lua` | 通过 `rendered.fields.*` 定位光标，不断言行文本 |
| `tests/render/detail_spec.lua`、`tests/unit/render_spec.lua` | 断言行文本、`---` 位置与组间偏移，需整体更新 |

列表卡片（#25）已经提供 `util.display_width` / `truncate_display` / `pad_display` 与
「边框区间与内容区间不重叠」的分段高亮约定，本方案直接复用，见关联文档。

## 方案

### 1. 卡片尺寸

在 `render.lua` 增加常量：

```lua
local DETAIL_CARD_MAX_WIDTH = 64
local DETAIL_CARD_MIN_WIDTH = 20
```

- 可用宽度 `available` 来自详情窗：`render.detail` 新增 `opts.width`；`Detail:render` 读取
  `nvim_win_get_width(self.win)`（或测试注入的 `self.width`）。
- `opts.width` 缺省时按 `DETAIL_CARD_MAX_WIDTH` 处理，保证 headless 直接调用
  `render.detail` 也能得到稳定输出。
- 卡片宽度 `W = min(DETAIL_CARD_MAX_WIDTH, max(DETAIL_CARD_MIN_WIDTH, available))`。
  - 窗口宽于 64：卡片固定 64，右侧留白，不拉伸。
  - 窗口窄于 64：`W` 跟随窗口收窄。
  - 窗口窄于 20 属于退化情形，按 20 输出，由 buffer 自身截断，不做额外处理。

### 2. 分组卡片

五组固定顺序与标题：

| # | 标题 | 字段 |
| --- | --- | --- |
| 1 | `状态信息` | id, status, tag, origin, openAt, closedAt, hash |
| 2 | `依赖与文档` | deps, doc, docParent |
| 3 | `提示词` | specPrompt, researchPrompt, codePrompt, verifyPrompt, docTaskSplitPrompt |
| 4 | `执行信息` | flow, touch, meta, isPrivateDesc |
| 5 | `决策说明` | decide, analysis, outstanding, eligible, blocked, stuck（仅 `analysis` 存在时） |

- 卡片之间只留一个空行；删除 `group_rule()` 与所有 `---`（包括 analysis 前那条）。
- 首行标题：`╭─ <标题> ` + 若干 `─` 填充 + `╮`，总宽 `W`；标题超宽时用 `…` 截断。
- 末行：`╰` + `─` 重复 `W - 2` + `╯`。
- 边框字符与标题文字分别上色：边框 `LoopKitMuted`（Comment），标题
  `LoopKitDetailSection`（Title），不新增高亮组。
- 标题之后第一张卡前保留 `# <任务标题>` 后的那一行空行；最后一张卡后接原有的空行与
  `# 任务描述`。

示意（`W = 40`）：

```text
# 产出跨包公共 API 支持矩阵

╭─ 状态信息 ──────────────────────────╮
│ id                              #232 │
│ status                      ◐ doing │
╰─────────────────────────────────────╯

╭─ 依赖与文档 ────────────────────────╮
│ deps                     #12, #13 │
│ doc   .pi/loop-kit/docs/nvim/2026- │
│       11-23T11-06-16-card-displa… │
╰─────────────────────────────────────╯
```

### 3. 键左值右的两列布局

对每张卡单独计算列宽：

- `inner = W - 4`（两侧各 `│ ` 与 ` │`）。
- `key_col = 该卡内所有键的显示宽度最大值`，并限制为
  `min(key_col, floor(inner * 0.45))`，最小 4；超限键用 `…` 截断。
- `gap = 2` 个空格；`value_col = inner - key_col - gap`。
- 普通行结构：`"│ " + pad_display(key, key_col) + "  " + value_field + " │"`。
- 值只有一行时**右对齐**：`value_field = pad_left_display(value, value_col)`，
  值末端与右边框之间只保留固定的 1 格内边距。
- 值需要折行时按聊天气泡处理：值列本身充当气泡宽度，每行在值列内左对齐并右补空格，
  续行的键列留空。
- 空值：`field(key, "")` 输出键名与全空格值列；`path_field` 未设置时仍输出
  `(未设置)` 并用 `LoopKitDetailMuted` 右对齐。

### 4. 聊天气泡式折行

实现一个通用的「段 → 行」折行器，输入是 `{ text, hl_group }` 段列表与目标显示宽度，
输出多行段列表，保留每段高亮与字节区间：

```lua
local function wrap_segments(segments, width)  -- returns rows of segments
```

规则：

- 按 `util.display_width` 累计宽度；只在字符边界切分，不产生半个 UTF-8 字符。
- 优先在空格处断行；当前行已用宽度超过目标一半且存在空格时回退到最后一个空格。
  CJK 等无空格文本按显示宽度逐字断行。
- 不做省略号截断，值内容完整保留（标题与键才允许 `…`）。
- 每个折行片段继承原段的高亮组；`deps` 的 `#12` id 高亮、`touch` 的
  `LoopKitDetailPath`、提示词路径在续行上保持同色。
- 折行后的首行参与第 3 节的右对齐；续行固定从值列起始位置开始，因此视觉上形成
  右对齐的「气泡」块。

多值字段：

- `touch`：键行放第一个路径，其余路径各占一行（值列内可继续折行），全部使用
  `LoopKitDetailPath`。空/未知状态沿用现有 `unknown`、`(empty)` 文本与 `LoopKitDetailMuted`。
- `deps`：仍用 `#1, #2` 串并在空格处折行，id 高亮随片段迁移。
- `analysis` 的 `outstanding` 等子项不再使用缩进 `- ` 前缀，改为同列的普通键值行。

### 5. 宽度来源与重排

`lua/loop-kit/ui/detail.lua`：

- `Detail.new` 保存 `self.width = opts.width`（测试可注入固定宽度）。
- `Detail:render(task, tasks_by_id, analysis, tasks)`：
  - 计算 `width = self.width`；若 `self.win` 有效则取 `nvim_win_get_width(self.win)` 覆盖。
  - 调用 `render.detail(task, { ..., width = width })`。
  - 记录 `self.last = { task =, tasks_by_id =, analysis =, tasks = }`。
- 新增 `Detail:rerender()`：用 `self.last` 重新渲染；无上次任务时跳过。

`lua/loop-kit/ui/board.lua` 的 `_resize()`（`:316-330`）：调整列表宽度后，如果详情窗存在且
上次渲染过，调用 `self.detail:rerender()`；用 `pcall` 包裹，避免关闭过程中的窗口失效报错。

详情 buffer 的 `wrap` 保持默认开启；卡片每行都不超过 `W`，正常情况下不会触发 Neovim
自身的折行。

### 6. 代码结构

在 `M.detail` 内新增局部辅助：

```lua
local function pad_left(text, width)            -- 复用 util.pad_left_display
local function kv_rows(key, value_segments, key_col, value_col)
local function card(title, body_rows)           -- 返回首行/末行与边框区间
```

- `out.fields[key]` 记录该字段**首行**的绝对行号；续行落在该锚点之后，`edit.M.target_at`
  的最近锚点逻辑无需修改。
- `deps` 的值区间偏移改为在段级生成后再折行，不再手工按 `2 + #"deps" + 2` 计算。
- 删除 `group_rule()`；`analysis` 分支改为构造 `决策说明` 卡片。

## 验收标准

- 单测：`tests/unit/util_spec.lua` 覆盖新增的 `pad_left_display`（刚好等宽、需补空格、
  已超宽原样返回、CJK 宽度），并确认既有 `display_width` / `truncate_display` 行为不变。
- 单测：`tests/unit/render_spec.lua` 覆盖 `render.detail` 的卡片结构：
  - `opts.width = 120` 时卡片总宽为 `64`（最大宽度生效），`opts.width = 50` 时为 `50`；
  - 每组都有完整的 `╭…╮` / `╰…╯` 与左右 `│`，行宽按显示宽度恰好等于 `W`；
  - 短值右对齐（断言值末尾与右边框之间恰好一个空格）、键左对齐；
  - 长 CJK 标题/路径按值列折行，续行从值列起始，内容不丢字符、不加 `…`；
  - `deps` 折行后 `#id` 区间仍为 `LoopKitDetailId`，`touch` 每个路径为
    `LoopKitDetailPath`，`doc` 未设置为 `(未设置)` + `LoopKitDetailMuted`；
  - 输出中不再出现 `---`；五组顺序与卡间单空行正确；`analysis` 存在时出现
    `决策说明` 卡且 `decide`/`outstanding` 等键值齐全；
  - `out.fields[key]` 指向各字段首行，且键值与值区间列偏移准确。
- 渲染比对：`tests/render/detail_spec.lua` 重写旧断言，检查 buffer 文本、卡片边框
  extmark 全部为 `LoopKitMuted`、卡片标题为 `LoopKitDetailSection`，并在
  `Detail:rerender()` 后按新宽度重新折行；`tests/fake-dom/board_spec.lua` 覆盖
  窗口变窄后详情行宽随之变化。
- 渲染比对：`tests/fake-dom/edit_spec.lua` 覆盖光标落在折行续行时仍解析到同一字段，
  避免编辑锚点回归。
- 全量：`nvim --headless -u tests/minimal_init.lua -l tests/run.lua` 全部通过；
  `git diff --check` 无输出；`loop-cli validate` 通过。
- 文档：README 与 `doc/loop-kit.txt` 的详情窗说明更新为分组卡片、最大宽度、键左值右与
  折行规则，并删除 `---` 分隔线的描述。
