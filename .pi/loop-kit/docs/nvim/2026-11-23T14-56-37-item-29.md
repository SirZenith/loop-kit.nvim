# 卡片内多行内容布局计算器（#29）

## 目标

解决 `touch` 这类「单个字段含多行内容」的键在任务详情卡片中的值布局问题：

- 新增一个可复用的纯函数布局计算器：输入视窗可用宽度、字符串列表（每个元素 = 一个独立
  排版行单位）与布局选项（对齐方式 left/right/center，默认 left；是否支持缩宽 shrink，
  默认 false），先按可用宽度对各元素做折行拆分，再逐行按对齐方式补齐空格，最后把全部
  结果放进一个平铺列表返回（同时返回最终视窗宽度）。
- 实现完成后直接应用到任务详情展示的 `touch` 字段：路径列表每个元素作为一个行单位传入，
  对齐方式 = 右对齐，开启缩宽支持。

## 现状

- 项目中尚无布局模块；多行折行只存在于 `lua/loop-kit/render.lua` 的局部函数
  `wrap_segments(segments, width)`（style-aware，按「过半宽处断空格、否则按字符边界」折行，
  仅 `render_card` 一处调用）。
- 详情卡片渲染：`M.detail(task, opts)`（`lua/loop-kit/render.lua`）把每个字段登记为
  `field(key, segments, blocks)`，由 `render_card(spec)` 统一排版：
  `key_col = max(4, min(key_width, floor(inner*0.45)))`，
  `value_col = max(1, inner - key_col - DETAIL_CARD_GAP)`（GAP=2，卡片宽 clamp 在 20..80）。
  逐 block 调 `wrap_segments(block, value_col)`；首行右对齐（键格 + 右侧补空格），
  续行左对齐（左侧补空格）；`out.fields[key]` 记录首行行号（`edit.lua:243-245` 的
  `target_at`、光标定位、`_edit_touch` 预填均依赖它）。
- `touch` 字段构造在 `lua/loop-kit/render.lua:729-747`：nil/vim.NIL/空串/空表 →
  `unset_seg()`（"N/A"）；string → `one_line` 压一行；table → 每个元素
  `seg(one_line(tostring(path)), "LoopKitDetailPath")` 作为独立 block 交给
  `field("touch", nil, touch_blocks)`。
- 宽度工具在 `lua/loop-kit/util.lua`：`display_width` / `pad_display` / `truncate_display`。
- 测试：`tests/run.lua` 自动发现 `tests/unit/*_spec.lua`，新测试文件无需注册；
  `tests/unit/render_spec.lua:628-657` 已钉死 doc 字段「首行右对齐、续行左对齐」的现有
  行为，`render_spec.lua:655-690` 覆盖 touch 的 N/A 与逐路径高亮用例。

## 方案

### 新模块 `lua/loop-kit/layout.lua`

纯函数、无 buffer/窗口依赖：

```lua
local layout = require("loop-kit.layout")
local rows, width = layout.compute(available_width, lines, opts)
```

- `available_width: number`：视窗可用显示宽度；`nil` 或 ≤0 时按 1 处理（先取整再 clamp）。
- `lines: string[]`：每个元素是一个**独立排版行单位**（元素之间绝不合并折行）。
- `opts.align: "left" | "right" | "center"`：默认 `"left"`；未知值按 `"left"` 处理。
- `opts.shrink: boolean`：默认 `false`。
- 返回 `rows: string[]`（平铺结果，**所有行等显示宽**）与 `width: number`（最终视窗宽度
  = 行宽）。

算法：

1. **宽度钳制**：`width = max(1, floor(available_width or 1))`。
2. **折行拆分（按字符边界，非空格断词）**：对每个行单位，用
   `vim.fn.strchars` / `vim.fn.strcharpart` 拆成字符 cell，`util.display_width` 计宽。
   逐字符累积，加入下一个字符会超宽时：**若当前行非空**则 flush 当前行、另起新行
   （必须先判 `if #row > 0 then flush() end`，否则「空行 + 超宽字符」会多产出一个空行）；
   **若当前行为空**（单个字符宽于可用宽度）则该字符独占一行（行可超宽）。宽字符不劈开、
   零宽字符吸附在前一字符上。每个折出行 trim 行尾 ASCII 空格。空字符串元素产出 1 个空行；
   空列表产出 0 行。
   选择字符边界折行而非沿用 `wrap_segments` 的空格断词，原因是它**无损**：逐行 trim 后拼接
   与原串完全相等（原型在宽度 12/25/31 下实测验证），而空格断词会丢掉断点处空格，
   `lua/with space/a.lua` 这类路径渲染后与源文本不一致。代价是与 `wrap_segments` 规则
   不同——本任务**不改动 `wrap_segments`**，两者规则差异在此记录为已知分歧；统一留待后续
   单独重构（`wrap_segments` 仅一处调用，风险可控）。
3. **目标宽度**：`shrink = true` 时 = 折行后各行的最大显示宽（≥1）；`shrink = false` 时
   = 钳制后的可用宽度。`shrink` 只改变行宽与返回宽度，**不改变任何可见字符**。
4. **对齐补齐**：把每行补齐到目标宽度：left → 右侧补空格；right → 左侧补空格；
   center → 左 pad 取 `floor(pad/2)`，右侧补剩余。

### 渲染层接入（`lua/loop-kit/render.lua`）

- `field()` 支持新增第四类参数形态 `layout = { lines = {...}, align = "right",
  shrink = true, hl_group = "LoopKitDetailPath" }`。
- `render_card` 遇到带 `layout` 的字段时：以该卡片的 `value_col` 调
  `layout.compute(value_col, lines, { align = ..., shrink = ... })` 得到 rows 与 width；
  **整块右锚**：`lead = value_col - width`（≥0），每行 = 键侧（首行键格 / 续行左侧补格）
  + `lead` 个空格 + row。选择右锚是为了保持 #27 确立的「键左值右」卡片风格（见关联文档）；
  此锚定下 shrink 的缩窄**在视觉上与不缩窄完全一致**（右对齐 + 右锚），shrink 的可观测
  定义就是「行宽 + 返回宽度」——它是为将来左锚/其它字段预留的 API，本次调用不改变画面，
  不视为缺陷。
- 高亮：布局器不返回高亮信息。渲染时对每个 layout 行做「去首尾 ASCII 空格」得到内容
  字节区间，按 `lead + 前导空格数` 的字节偏移 `push_hl(hl_group)`，避免把补齐空格标成路径。
- `touch` 字段构造改为：nil/vim.NIL/空串/空表 → 维持 `unset_seg()` 现状（不走布局）；
  string → `lines = { one_line(touch) }`；table → `lines = 每个元素 one_line(tostring(path))`；
  两者都以 `align = "right"`、`shrink = true`、`hl_group = "LoopKitDetailPath"` 走布局块。
- `out.fields.touch` 仍指向第一视觉行，`edit.lua` 的 `target_at` / 光标行 / `_edit_touch`
  预填（读 `task.touch` 原始值）均不受影响。

## 验收标准

- [单测] 折行无损且按字符边界 —— `tests/unit/layout_spec.lua`：宽度 12/25/31 下对含
  空格与 CJK 的输入逐行 trim 后拼接与原串完全相等；宽字符不被劈开。
- [单测] 对齐补齐正确 —— `tests/unit/layout_spec.lua`：left 右补、right 左补、center
  左 pad = `floor(pad/2)`；含 CJK 行按显示宽补齐；未知 align 按 left。
- [单测] shrink 语义 —— `tests/unit/layout_spec.lua`：`shrink = true` 时返回 width =
  折行后最宽行显示宽、所有行等宽且不含补齐空格差异；`shrink = false` 时 width = 钳制后
  可用宽度；两种取值下各行可见字符完全一致。
- [单测] 边界行为 —— `tests/unit/layout_spec.lua`：空列表 → 0 行；空字符串元素 → 1 行；
  宽度 nil/≤0 → 按 1；单字符超宽时独占一行且不虚增空行。
- [单测] touch 渲染走布局 —— `tests/unit/render_spec.lua` 扩展 touch 用例：长路径在
  `value_col` 处折行；`fields.touch` 指向第一视觉行；每个 touch 行恰一个
  `LoopKitDetailPath` 高亮且区间不含前导/尾随补齐空格。
- [单测] 既有行为不回归 —— `tests/unit/render_spec.lua` 全绿，特别是 `:628-657` 的
  doc 字段「首行右对齐、续行左对齐」与 `:655-690` 的 touch N/A 用例（`wrap_segments`
  输出不得改变）。

## 待确认决策

无。调研遗留的四个取舍已在本文档定案：缩窄块右锚（保持「键左值右」风格，shrink 视觉
中性、作为预留 API）、折行按字符边界（无损优先，不动 `wrap_segments`）、string 形态
`touch` 维持 `one_line` 压一行后作为单个行单位走布局、shrink 的可观测定义为「行宽 +
返回宽度」。
