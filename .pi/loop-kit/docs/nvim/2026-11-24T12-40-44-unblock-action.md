# 看板解除任务阻塞（blocked → pending）

## 目标

在看板内提供一个显式动作，把状态为 `blocked` 的任务改回 `pending`，用户无需切到终端
执行 `loop-cli edit <id> --status pending`。

交付面按已确认的决策固定为：

- 键位 `u`、命令 `:LoopKit unblock <id>` 与 Lua API `M.unblock(id)` 三种入口。
- 不做二次确认，直接写回；离开 blocked 后由 provider 清空 `blockedReason`。
- 同时支持 local 与远端（gitea / github / jira）。
- 仅当条目当前状态是 `blocked` 时执行；否则提示当前状态，不发起写请求。

约束与边界：

- 所有写回仍走 `loop-cli edit <id> --status pending`，不直接改 `LOOP.json`、
  `loop.meta.json` 或远端 issue 标签。
- 不传 `--force`：该参数只影响 `done` 的依赖关闭门禁，对 `blocked → pending` 无意义。
- 远端写回受 `updatedAt` 乐观并发校验约束；冲突沿用现有 conflict 文案，不自动重试。
- 功能取舍以 `.pi/loop-kit/TARGETS.md` 的功能集与用户体验为准；该文件当前仍是待填写模板，
  本次按“看板内完成任务生命周期动作”的既有边界实现。

## 方案

### 1. 动作层 `lua/loop-kit/actions.lua`

在 `Actions:block` 之后新增：

```lua
--- Move a blocked task back to pending (blocked → pending).
function Actions:unblock(id, cb)
  cb = cb or noop
  id = util.normalize_id(id)
  if not id then
    self:_settle(self:_invalid("unblock", id), cb)
    return
  end

  local task = nil
  for _, item in ipairs(self.state.tasks) do
    if item.id == id then
      task = item
      break
    end
  end
  if not task then
    self:_settle(self:_invalid("unblock", id, "未找到任务 " .. id), cb)
    return
  end
  if task.status ~= "blocked" then
    self:_settle(self:_invalid("unblock", id,
      string.format("条目 %s 当前状态是 %s，不是 blocked", id, tostring(task.status))), cb)
    return
  end

  self:_submit("unblock", id, "edit", { id, "--status", "pending" }, {}, function(res)
    self:_settle(res, cb)
  end)
end
```

要点：

- 复用 `_invalid` 的 `code = "invalid"` 与 `kind = "usage"`，这样看板只提示、不重试。
- 从已加载的 `self.state.tasks` 判定状态，避免为一次守卫多跑一次 `list`。
- 不新增 `confirm.unblock`；与 `claim` 一样零确认。

### 2. 看板 `lua/loop-kit/ui/board.lua`

- `DEFAULT_KEYS` 增加 `u = "unblock"`。
- `ACTIONS` 增加：

```lua
  unblock = function(self)
    local id = self:_selected_id()
    if id then
      self:_ensure_actions():unblock(id, function(res)
        self:_after(res)
      end)
    end
  end,
```

### 3. 帮助与公开入口

- `lua/loop-kit/ui/help.lua` 的 `KEY_LINES` 在 `b` 之后增加
  `{ "u", "解除阻塞（blocked → pending，直接执行）" }`。
- `lua/loop-kit/init.lua`：
  - `SUBCOMMANDS` 增加 `"unblock"`；
  - 新增 `M.unblock(id, opts)`，结构同 `M.remove`，最终调用 `instance:handle("unblock")`；
  - `M.command` 增加 `elseif sub == "unblock" then return M.unblock(parts[2])`。

## 验收标准

- [单测] `tests/fake-dom/actions_spec.lua`：对 blocked 任务调用 `act:unblock("#12")` 时，
  首个进程 argv 为 `--project-root <root> --json edit #12 --status pending`，且不含
  `--force`；回包后 `state:selected().status == "pending"`、`res.action == "unblock"`。
- [单测] `tests/fake-dom/actions_spec.lua`：目标状态为 `pending` / `doing` / `done` 时返回
  `ok = false`、`code = "invalid"`，消息包含“不是 blocked”，且 `f:call_count() == 0`
  （不发起写请求）。
- [单测] `tests/fake-dom/actions_spec.lua`：未知 id 返回 `code = "invalid"` 且不 spawn。
- [单测] `tests/fake-dom/actions_spec.lua`：模拟 `edit` 退出码 4 且 stderr 含
  “冲突：远端已被更新”时，`res.conflict == true`，消息包含
  “远端任务已更新：请同步后人工核对，不会自动重试。”，且总调用次数仍为 1（不自动重试）。
