# 二次确认悬浮弹窗组件

## 目标

条目 #21（#18 的实现子项，flow: spec-impl）：二次确认界面以独立 UI 组件实现——悬浮弹窗内用文本显示询问内容，最下方横向排列选项按钮，`h`/`l` 左右切换选中按钮，回车确认选中，Esc（及 `q`）取消。替换现有 4 处走 `vim.ui.select` 的默认确认实现，同时保留测试注入缝不受影响。人工观感验收由父条目 #18 的人工验收子项负责，不属本条目范围。

## 现状

- 项目中所有确认交互仍走 `vim.ui.select` / `vim.fn.confirm`，外观与键位由用户 UI 插件决定，无统一悬浮确认组件。
- 已有两处浮窗先例可复用范式：
  - `lua/loop-kit/ui/picker.lua`：`M.multi(opts)` 多选浮窗，`nvim_create_buf(false, true)` + `bufhidden="wipe"`、`style="minimal"` + `border="rounded"`、`closed` 标志防重入、draw 时临时置 `modifiable`。
  - `lua/loop-kit/ui/help.lua`：`M.open(opts)` 帮助浮窗，宽度用 `vim.fn.strdisplaywidth` 计算并夹取 `columns-4`，`title_pos="center"`、`vim.wo[win].wrap=false`、模块级单例（已开则聚焦）。
- 高亮组 `LoopKitSelected = "Visual"` 已在 `lua/loop-kit/highlights.lua` 定义（`default = true`，可被用户覆盖）。
- 待接线的 4 处默认实现（均用 `vim.ui.select`）：
  - `lua/loop-kit/actions.lua`（约 17–25 行）：boolean 确认 `default_ask(prompt, cb)`，调用点 actions.lua:442、511（完成确认等）。
  - `lua/loop-kit/advanced.lua`（约 225–230 行）：boolean 确认 `default_ask`，调用点 advanced.lua:508（删除阶段等破坏性操作）。
  - `lua/loop-kit/ui/board.lua`（约 717–735 行）：choice 确认 `Board:_edit_ask(prompt, options, cb)`，调用点 board.lua:843、978、1001。
  - `lua/loop-kit/edit.lua`（约 328–333 行）：choice 确认 `default_ask(prompt, options, cb)`，调用点 edit.lua:473。
- 测试基建：`nvim --headless -u tests/minimal_init.lua -l tests/run.lua [-- --filter unit|fake-dom|render|integration]`；目录 tests/unit、tests/fake-dom、tests/render、tests/integration，文件命名 `*_spec.lua`。
- 现有 `ask` / `edit_ask` / `form_ask` 注入缝全部保留：fake-dom 测试注入假实现时路径不变。

## 方案

采用**自研浮窗组件**（新文件 `lua/loop-kit/ui/confirm.lua`），与 picker/help 同一范式：

- 否决 `vim.fn.confirm()`：命令行区按钮、键位 1/2/3，不满足「悬浮 + h/l」。
- 否决沿用 `vim.ui.select`：外观与键位由用户 UI 插件决定，无法保证 h/l 与按钮布局。
- 否决引入 nui/dressing：违反 README 零依赖约束。

### 关键接口 / 数据形状

```lua
-- lua/loop-kit/ui/confirm.lua
local M = {}

--- 纯函数：构造模型。options 元素为 string 或 { label = string, value = any }。
M.new_model({ prompt = string, options = {...}, default = 1 })
  -> { prompt, options = { { label, value } }, cursor = 1..n }

M.move(model, delta) -> cursor        -- 两端环绕
M.current(model) -> value, index

--- 纯函数：布局。返回文本行与按钮高亮区间（字节偏移，row 为 0-based）。
M.lines(model, width) -> lines: string[], spans: { { row, col, end_col, index } }

--- 打开浮窗；回调保证恰好一次（选中或取消，二者其一）。
M.open({
  prompt, options, default?, title? = " 确认 ", width?,
  on_select = fun(value, index), on_cancel = fun(),
}) -> handle
-- handle: { buf, win, model, is_open(), close(), current() }

--- 便捷封装
M.ask(prompt, opts, cb)    -- cb(value, index)；取消传 nil
M.boolean(prompt, cb, opts?)  -- 确认/取消；取消 cb(false)
M.choice(prompt, options, cb) -- 字符串选项原样回传；取消 cb(nil)（兼容 vim.ui.select 语义）
```

### 渲染与交互规范

- **布局纯模型 + 手工换行 + extmark 高亮**：`lines(model, width)` 逐字符按 `vim.fn.strdisplaywidth` 换行（文本内宽 `width-4`）；行结构为「提示词若干行 / 空行 / 按钮行」；按钮形如 `[ 确认 ]  [ 取消 ]`。`lines` 同时返回按钮的**字节区间**，渲染时用 extmark（`end_col` 是字节偏移）给选中按钮整段打 `LoopKitSelected` 高亮。CJK 宽度必须用 `strdisplaywidth` 计算，禁止用显示列反推字节列。
- **窗口配置**：`width = min(72, max(28, columns-10))` 且至少容纳按钮行 + 4；居中（row/col 由 lines 长度与 width 计算）；`nvim_create_buf(false, true)` + `bufhidden="wipe"` + `swapfile=false`；`style="minimal"` + `border="rounded"` + `title_pos="center"` + 默认 `zindex`；`noautocmd=true`；`vim.wo[win].wrap = false`、`cursorline = false`。draw 时仿 picker 临时置 `modifiable`。
- **键位（buffer-local）**：`h`/`<Left>` 与 `l`/`<Right>` 环绕移动、`<CR>` 确认、`<Esc>` 与 `q` 取消。buffer-local 映射优先于全局映射，不会误触看板映射。
- **关闭语义**：先置 `closed = true` 再 `nvim_win_close`；`WinClosed`（pattern = `tostring(win)`）兜住 `:q` / `:close` / 父 tab 关闭等外部关闭路径，触发 `on_cancel`；关闭后焦点自动回到原窗口（回调前显式恢复 `prev_win` 兜底）。回调恰好一次。
- **并发**：模块级单例——新确认打开前先取消（触发 `on_cancel`）旧实例，避免按键落点混乱。
- **安全默认值**：破坏性操作（删除阶段、放弃修改、清除 meta 等）由调用方显式传 `default` 指向「取消/继续编辑」，避免回车误确认；非破坏性（如完成确认）默认「确认」。

### 接线

将 4 处默认实现替换为 confirm 组件（注入缝分支不动）：

| 文件 | 现状 | 改后 |
| --- | --- | --- |
| `lua/loop-kit/actions.lua` | `default_ask` 用 vim.ui.select | `require("loop-kit.ui.confirm").boolean` |
| `lua/loop-kit/advanced.lua` | `default_ask` 用 vim.ui.select | 同上，破坏性调用显式 `default` = 取消 |
| `lua/loop-kit/ui/board.lua` | `_edit_ask` 兜底 vim.ui.select | 兜底改 `confirm.choice` |
| `lua/loop-kit/edit.lua` | `default_ask` 用 vim.ui.select | 兜底改 `confirm.choice` |

调用方签名（`cb(boolean)` / `cb(choice)`）不变，fake-dom 测试注入路径不受影响。

## 验收标准

- [单测] 模型与布局纯函数 —— 断言于 `tests/unit/ui_confirm_spec.lua`：
  - `new_model` 归一化 string / `{label,value}` 两种 options，`default` 夹取到 1..n；
  - `move` 两端环绕（cursor=1 左移 → n；cursor=n 右移 → 1）；
  - `current` 返回选中项 value 与 index；
  - `lines(model, width)`：CJK 提示词按显示宽度换行、行数 = 提示行 + 空行 + 按钮行；spans 的 `col`/`end_col` 是按钮文本的字节区间（含「确认」等 CJK 时字节偏移与 `strdisplaywidth` 一致），每个 span 的 index 对应按钮序号。
- [渲染比对] 浮窗真实行为 —— 断言于 `tests/render/ui_confirm_spec.lua`（headless nvim，`nvim --headless -u tests/minimal_init.lua -l tests/run.lua -- --filter render`）：
  - `M.open` 后 `nvim_win_get_config(win)` 回读 `style="minimal"`、`border="rounded"`、`focusable=true`，buffer `bufhidden="wipe"`，窗口行数 == `lines()` 返回行数（wrap=false）；
  - `nvim_feedkeys(nvim_replace_termcodes("l",true,false,true),"x",false)` 后 `nvim_buf_get_extmarks` 高亮区间移到第二个按钮（字节区间与 `lines` 的 spans[2] 一致）；再按 `h` 回到第一个；`q`/`<Esc>` 触发 on_cancel 且窗口关闭；
  - `<CR>` 触发 `on_select(value, index)` 且恰好一次；关闭后 `nvim_get_current_win()` 等于打开前的 win id；
  - 外部 `nvim_win_close(win)` 触发 on_cancel 恰好一次（WinClosed 兜底）；
  - 打开第二个确认时第一个被取消（on_cancel 触发一次）且旧窗口已关闭；
  - `M.boolean` 取消 → cb(false)；`M.choice` 取消 → cb(nil)、选中 → 原字符串回传（vim.ui.select 兼容语义）。
- [人工] 真实终端观感（按钮高亮可读、边框/标题居中、无跳变）——由父条目 #18 拆分出的人工验收子项承担，不在本条目（#21）验收范围。
