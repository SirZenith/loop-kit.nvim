# 看板列表与详情自动刷新

## 目标

后台 loop 在本机修改任务状态或元数据后，已打开的看板应在约 1 秒内自动更新左侧任务列表与右侧
任务详情，不需要用户按 `r` 或重新打开看板。

约束与边界：

- 不改变 loop-cli 的读写协议，不新增依赖，不引入常驻 CLI 进程。
- 本机缓存监听默认开启、零网络；其它机器对远端的修改依靠切回 Neovim 时的
  `FocusGained` 后台同步兜底。
- 手动刷新（`r` / `R`）与现有写后刷新语义保持不变。
- 自动刷新必须保留当前选中、列表光标与详情滚动位置；没有实际变化时不重绘、不触发
  `LoopKitUpdated`。
- 编辑、写操作、同步进行中一律跳过，避免覆盖编辑缓冲或产生竞态。

## 现状

### 刷新触发点

| 时机 | 行为 |
| --- | --- |
| 首次打开看板（`lua/loop-kit/ui/board.lua:1657-1668`） | `refresh({ no_sync = true, then_sync = true })`：先读缓存，远端源再后台 `sync()` 并重绘（`board.lua:574-582`） |
| 已打开时再次 `open`（`board.lua:1630-1632`） | 只 `focus()`，不拉取数据 |
| 写操作成功后（`lua/loop-kit/actions.lua:254-303`） | `reload()` 默认 `source:list({ no_sync = true })`（`actions.lua:67`）→ `state:set_tasks` → 重绘；remove 额外重选邻居 |
| 写操作后的 `_maybe_sync`（`actions.lua:299-308`） | 非 local 源后台 `source:sync(noop)`，只更新缓存，不重绘 |
| 进阶操作（`lua/loop-kit/advanced.lua:311-360`） | 与写操作相同的缓存刷新 |
| 详情字段编辑保存（`board.lua:897-905`） | 读缓存并重绘 |
| `VimResized`（`board.lua:310-315`） | 只做 `_resize()`，不拉取数据 |

现有实现没有定时器、`FocusGained`、文件监听或轮询；只有显式 `r`（`board.lua:1480-1481`）与
`R`（`board.lua:1484`）会再次刷新。

### 可监听的数据面

任务状态最终落在本机文件：

- local 源：`LOOP.json`（配置里的 `filePath` 可覆盖文件名）。
- 远端 / Lua 源：`LOOP.remote.json` 与 `loop.meta.json`。

远端源在每次写操作后会立即把强一致的单条结果合并进 `LOOP.remote.json`，不是只在 `sync`
时才写；而 `loop-cli list --no-sync` 只读这些缓存文件，不联网。因此本机后台 loop 的变化可以
不经过网络、直接由文件变化感知。

### 详情为什么能一起刷新

`Board:draw()`（`lua/loop-kit/ui/board.lua:513-528`）每次都会调用 `_draw_detail()`
（`board.lua:485-511`），后者从最新 `state` 重新渲染当前选中任务。因此列表刷新后详情自然
同步；`State:_restore`（`lua/loop-kit/state.lua:147-190`）会保留仍可见的选中 id，`Detail:render`
通过 `nvim_buf_set_lines` 重写（`lua/loop-kit/ui/detail.lua:25-38`），光标行与 topline 保持。

### 已知缺口

- 跨机器修改远端任务不会写本机缓存，文件监听感知不到。
- README 把 `auto_sync` 描述为「打开/刷新时」后台同步，但代码只有首次打开传 `then_sync`；
  按 `r` 不会后台同步。该描述应一并修正。

## 方案

### 1. 新增 `lua/loop-kit/watch.lua`

轻量文件签名监视器，只负责「变了就回调」，不做 IO 刷新：

- `M.files(dir)` 返回 `LOOP.json`、`LOOP.remote.json`、`loop.meta.json` 三个路径；缺失文件也
  计入签名，创建/删除都能触发。
- `M.signature(paths, stat)` 拼接 `mtime.sec`、`mtime.nsec`、`size` 与缺失标记。
- `M.new({ paths, interval, on_change, stat, new_timer, start })`：
  - `interval` 默认 1000ms，最小 200ms；
  - 首次 tick 只建立基线，不触发回调；
  - 定时器用 `vim.schedule_wrap` 回到主循环，`unref()` 避免阻止 Neovim 退出；
  - `start = false`、`stat`、`new_timer` 供单测注入。
- `Watch:tick()` 比较签名，变化时更新基线并调用 `on_change`。
- `Watch:stop()` 停止并关闭 timer，可重复调用。

### 2. 看板接入（`lua/loop-kit/ui/board.lua`）

- `M.config`（`board.lua:63-71`）新增：
  - `watch = true`
  - `watch_interval = 1000`
  - `sync_on_focus = true`
- `M.open`（`board.lua:1624-1670`）注册 autocmd 后调用 `self:_start_watch()`，并把
  `opts.watch` / `opts.watch_interval` / `opts.sync_on_focus` 解析到实例字段（`nil` 时取
  `M.config`）。
- `Board:_start_watch()`：
  - watch 目录取 `opts.loop_root`，其次 `self.config.loop_root_hint`，最后
    `vim.fs.joinpath(root, ".pi", "loop-kit")`；
  - 目录不存在时直接返回（测试用的 fake 项目根天然不启动定时器）；
  - 创建 watcher 并保存到 `self._watch`。
- `Board:_watch_changed()`：

```lua
if self.closed or self.editing or self.syncing then return end
if self.state and self.state:is_writing() then return end
self:refresh({ no_sync = true, quiet = true, skip_unchanged = true })
```

- `Board:refresh`（`board.lua:531-590`）新增两个语义：
  - `quiet`：不设置 `self.syncing` 的开始态；失败时不写 `self.load_error`、不重绘，保留旧快照；
  - `skip_unchanged`：调用 source 前记录旧 `tasks` 与 `analysis`，完成后用 `vim.deep_equal`
    比较。相同则不 `set_snapshot`、不 `draw`、不触发 `on_updated`；但 `opts.after`
    （编辑保存后的回焦）与 `then_sync` 仍必须执行。
- `Board:_on_focus()`：

```lua
if self.closed or self.editing or self.syncing then return end
if not self.sync_on_focus or not self.source then return end
local now = vim.uv.now()
if self._focus_at and now - self._focus_at < 2000 then return end
self._focus_at = now
self:refresh({
  no_sync = true, quiet = true, skip_unchanged = true, then_sync = true,
})
```

- 在 `_register_autocmds`（`board.lua:286-316`）注册 `FocusGained`，回调 `self:_on_focus()`。
  `then_sync` 已区分源类型：local 不联网；远端先渲染缓存，再后台 `sync()` 并用新结果重绘。
- `Board:_teardown`（`board.lua:356-395`）在 `closed = true` 后调用 `self:_stop_watch()`
  （`stop()` 并置 nil），避免 timer 泄漏。

### 3. 配置透传（`lua/loop-kit/init.lua`）

- `defaults()`（`init.lua:25-53`）新增 `watch = true`、`watch_interval = 1000`、
  `sync_on_focus = true`。
- `M.setup()`（`init.lua:62`）与 `M.reset()`（`init.lua:84`）的 `board.setup({...})` 转发三个字段。
- `M.open()`（`init.lua:188`）在选项回退处处理三个字段，并传
  `opts.loop_root = opts.loop_root or (resolved and resolved.loop_root_hint)`，兼容自定义
  `loopRoot`。

## 验收标准

自动档：

1. `nvim --headless -u tests/minimal_init.lua -l tests/run.lua` 全绿；`git diff --check` 无输出。
2. `tests/unit/watch_spec.lua`：
   - `M.files` 路径正确；
   - 签名在 mtime、size、文件缺失/创建时变化；
   - 首次 `tick` 不触发，变化只触发一次，无变化不重复触发；
   - `stop()` 调用 timer 的 stop/close。
3. `tests/fake-dom/watch_spec.lua`：
   - `_watch_changed()` 后列表出现新状态、详情出现新描述；
   - 相同响应不重复触发 `on_updated`；
   - `board.editing` 非空时 `_watch_changed()` 不发起请求；
   - `watch = true` 时 `_watch` 存在，`close()` 后为 nil；
   - 真实 timer 用例：`watch_interval = 200`，改写文件后 `vim.wait` 内 fake `list` 调用次数增加。
4. `tests/integration/public_spec.lua` 断言 `watch = true`、`watch_interval = 1000`、
   `sync_on_focus = true`。

延后（人工）：

- 另一终端运行 `/loop`，看板保持打开，任务从 pending→doing→done 在约 1 秒内反映到列表与详情。
- 后台刷新时选中任务、列表光标与详情滚动不跳。
- `watch = false` 后不再自动刷新；`sync_on_focus = false` 后切回 Neovim 不发起网络同步。
- 其它机器修改远端任务后，切回 Neovim 能通过 `FocusGained` 同步看到变化。

## 待确认决策

- Windows 时间戳精度：签名已含 `nsec` 与 `size`；若仍出现同秒同大小覆盖漏检，可把
  `watch_interval` 降到 500ms，或后续增加内容 hash 模式。
- 多看板同时打开时，`FocusGained` 会为每个看板各触发一次缓存读取；当前用每看板 2 秒节流
  控制成本，暂不按 tabpage 可见性过滤。
- 选中任务被后台完成且从当前筛选消失时，按既有 `State:_restore` 语义切到相邻任务，不做额外提示。
