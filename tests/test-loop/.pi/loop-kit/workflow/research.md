本文件描述「实现前调研」的标准（默认标准；项目可在 `loop/workflow/research.md` 覆盖）。

在写实现文档、测试或代码之前，先完成对目标需求的调研；确有来自项目外、将来可复用的知识时，
再把它固化为文档。

# 输入

- 目标条目：`id`、标题、`desc`、`tag`、`deps`（用 `loop-cli show <id>` 读取；提示词已给出 id）。
- 项目准则：循环数据目录的 `TARGETS.md`（含「任务分类（tag）」）、项目根 `CONTEXT.md`。
- 相关现有代码与文档。

# 调研范围（按 tag 选择侧重点）

- `feature`：调研市面可用方案，比较易用性、可维护性、可扩展性，重点是与本项目现有架构的
  契合度。
- `ux`：考察同类应用如何实现该体验、如何呈现、为何如此设计，判断是否比项目现状更符合
  `TARGETS.md`。
- `visual`：考察同类界面的视觉处理惯例与项目中可行的样式手段。
- `bugfix` / `refactor` / `docs` / `chore`：调研根因或既有模式，确认与项目约定一致的做法。

# 调研方法

- **先检索已有结论**：用只读工具 `search_loop_knowledge`（`keywords` 必填，`limit` 默认 8）检索
  `knowledge/` 与 `docs/`，命中后再用 `read` 读全文；有现成结论就不必重复调研。
- 优先一手来源（官方文档、源码、可复现实验）。
- **可证伪优先**：能用确定性实验或断言验证的行为，优先用可复现实验验证（档位见 `docs/workflow.md`
  的「测试与验证档位」）。**无浏览器 ≠ 无验证**：真实浏览器只是可选增强，不是前提。
- 「本会话没有 X」这类判断句必须附探测命令与原始输出，否则只能写「待确认」。
- **不得向用户提问**，须自行查证并作出判断。

# 能力探测与证据

- 打算使用浏览器 / 网络 / 设备等能力时，先探测：
  - 可用：该能力覆盖的部分必须实测，并记录命令 / 断言与原始结果。
  - 不可用：在产物中**原样粘贴**探测到的错误，并**不得**把相关结论写成「已验证 / 已核对」；
    这些项交给验收步骤按 `verify.md` 拆成需人工条目，**不因此把整轮判为失败**。
- 需要浏览器实测的项只能在主会话完成（子会话拿不到连接）；你只负责记录探测结果并把边界
  交接给验收步骤。

# 产物（知识固化，可选）

- 只有确实存在「来自项目外、将来可复用」的知识时，才写成循环数据目录的 `knowledge/<域>/<title>.md`。
  `<域>` 取该知识所属主题（`core` / `gui` / `providers` / `judge` / `pi` / `process`，
  或按项目实际情况新增）；`<title>` 为概括性短标题（小写英文短横线分隔）；
  内容至少含：**结论**、**依据/来源**、**对本项目的适用性判断**。引用时写完整路径
  `loop/knowledge/<域>/<title>.md`。
- 新知识文档必须以 YAML 头开始（字段与规则见本 prompt 的「标准：knowledge」）：`summary`
  单行 ≤120 字（写「对象 + 结论」，不含 Markdown）、`domain` 与所在目录一致、`tags` 行内列表、
  `updated` 为 `YYYY-MM-DD`。缺头的文档会被一致性测试拒绝；检索工具与后续步骤**先读头再决定
  是否读全文**。
- 没有值得固化的知识时**不写任何文件**：不创建空文档，在最终回复中说明「无需固化 knowledge：<原因>」。
- 自动循环中，最终回复会被编排器转交给后续 spec / 验收步骤，是本轮调研结论的交接物。
  即使不写文件，回复也必须自包含：核心结论、关键接口 / 数据形状、风险与未决问题。
- 调研已能确定实现方式时，把结论**简要**留给后续步骤复用，不必重复成文。
- 确有 knowledge 文档时，它不单独提交，随后续实现提交一并带入（项目另有规定从其规定）。

# 边界

- 只做调研与（按需的）知识固化：**不写实现代码、不改条目 `status`、不生成实现文档**。
- 不执行 `git push` 或任何远程写操作。

# 被复用时的行为（同 agent 续查）

提示词可能带上一次调研的 `sessionID`（带历史启动）。先看历史里已查过什么、已排除什么，
只补缺口；已固化的 `knowledge/*.md` 是长期交接载体，本轮最终回复也会转交后续步骤，
补查结论照常写入 knowledge（如确有可复用知识）；发现旧结论有误时**明确纠正**并更新文档，不要默默覆盖。
