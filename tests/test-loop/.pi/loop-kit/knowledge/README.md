# knowledge/ —— 调研知识索引

按域分目录存放「从项目之外取得、值得固化」的调研：修 bug 前的事实核对、新需求的技术可行性、
外部 API 契约、设计模式证据等。文件名沿用短标题（不带时间戳——调研会被反复引用）。

```
knowledge/<域>/<slug>.md
```

- `<域>` 取该知识所属主题（示例：`core` / `gui` / `providers` / `judge` / `pi` / `process`，
  也可按项目实际情况新增）。
- 引用时写完整路径 `loop/knowledge/<域>/<slug>.md`，便于跨目录检索。

## 索引

```text
knowledge/
└── core/    # 核心逻辑、数据结构、协议契约
```

新增文档时在这棵树里补上文件名（或加一个域目录行），写清该域收什么，避免同一主题散落多处。
